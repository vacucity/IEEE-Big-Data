# 历史证据门槛：正式窗口适用性核对

2026-11-07。本核对没有生成、修改或上传提交包；Kaggle 公榜和私榜的真实成绩未知。

## 门槛与本地结果

原规则仅在 constr 持续排队窗口接受 10% 历史案例建议的 0→1 翻转。新增门槛：同一格的 30 个历史匹配起点至少20个有有效观测，历史排队比例比 CPU 条件概率高至少 0.30。

在已反复探索的 251 个 March 代理窗口中，原规则 +0.000648875，门槛后 +0.000676112，差 +0.000027237；原规则改56格，门槛后36格，得分变好的窗口9个、变差4个。相对原规则的按日 bootstrap 95% 区间 [-0.000406,+0.000411]，含0；因规则根据这些数据反复探索，该区间不校正选择偏差。另11个同月窗口没有分数变化，其中没有 D7_I210_W，不能对该路段形成独立确认。

## 正式窗口会改哪里

本轮在8个排队面板、每个面板 validation 和 private 各5个 ongoing 正式窗口，共80窗，按照同一训练历史、CPU 模型概率和窗口分类检查。正式 onset 没有检查。正式窗口的未来真实标签不公开，本轮没有对其评分。

首先计算 CPU 规则相对 CPU 基准的 0→1 净变化，再作用于 V84 原始提交的同一位置。这样不会把原始提交与 CPU 自身重放的差异直接当作门槛收益；80窗中门槛实际改动涉及的6个窗口均不存在 CPU 整窗口回放不一致。统计不改变原提交：

| 范围 | 门槛前建议会改变原 V84 的格子 | 门槛后会改变原 V84 的格子 |
|---|---:|---:|
| validation，40窗 | 9 | 8 |
| private，40窗 | 3 | 2 |

门槛后的8个 validation 格子属于4个窗口，2个 private 格子属于2个窗口。具体2个 private 格子分别在 D7_I10_E 和 D12_I5_S。它们是正式 private 输入中按规则计算的修改位置，不是已确认的正确答案；能否提高官方分数未知。

针对此前重点关注的 D7_I210_W，validation 的两个原规则改动中：L210W-004 的有效历史只有14个，被20个的门槛挡住；L210W-028 有22个有效历史且概率差满足要求，被保留。该路段的5个 private 窗口在原规则及门槛规则下均无提交值改变。其他路段的私榜改动解释了为何整个8面板统计中仍有2个 private 格子。

## 复核范围

`official_gate_windows_audit.csv` 记录80窗口；`official_gate_cells_audit.csv` 记录门槛前12个候选有效改动及各自历史样本数、模型概率、门槛结果；`official_gate_summary.json` 和 `official_gate_verification.json` 为汇总和检查。核对了80窗口唯一性、门槛逐格算式、原 D7_I210_W 审计结果一致，并将12个候选格映射回原始 V84 ZIP，确认原值为0。脚本 `work/analog_gate_official_audit.py` 和 `work/verify_analog_gate_official.py` 只做只读审计。

正式窗口匹配使用目标时刻 T 及之前的观测，历史案例来自 March 之前的训练月；阈值使用已发布观测和 CPU 模型输出。历史案例的未来观测用于估计概率，不是被预测窗口的未来真值。正式输出的隐藏标签没有读取，任何“改对”或“改错”的表述都无法支持。

这只是正式窗口应用范围的确认，不是完整上榜复现或精度验证；可能受历史观测噪声、训练数据与目标月份分布差异以及 CPU/GPU 实现差异影响，最终公榜或私榜是否提高仍未知。若要研究不同规则，应在未用于选规则的月份、基模型亦未训练该月的预测上测试，且单独核对 onset。
